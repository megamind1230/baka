*** Why many people eventually leave Obsidian for Emacs
The biggest difference isn't features---it's integration.
In Obsidian, your notes, Git, terminal, coding, task management, AI
tools, and project navigation are all separate pieces connected by
plugins or external applications.
In Emacs, they're all part of the same environment. You can write
documentation, jump to source code, stage changes with Magit, run tests
in a terminal, update your agenda, insert links to notes with
=org-roam=, and search your entire knowledge base with =consult-ripgrep=
without leaving the editor.
Since you already use Emacs and work on software projects like your
=chrono= TUI app, consolidating your workflow there has another
advantage: your notes live alongside your code, and you can freely
choose between Org mode for rich planning and Markdown when you need
GitHub-compatible documentation. You're no longer constrained to a
Markdown-only ecosystem, but you also don't lose Markdown support.
If I were setting up a fresh "Emacs as Obsidian" configuration in 2026,
I'd start with just these packages:
- =vertico=, =consult=, =orderless=, =marginalia=, =embark=
- =which-key=
- =org-modern=
- =org-roam=
- =markdown-mode=
- =org-download=
- =olivetti=
- =dirvish=
- =magit=
- =eat=
That combination gets you very close to the convenience of Obsidian
while unlocking capabilities that go well beyond what Obsidian is
designed to do.

**** 2. What does =Shift-K= / =manual-entry= do in Emacs?
In Emacs, =C-h k= means: *Describe key*
But =Shift-K= (=K=) is usually bound to: manual-entry (man pages but
inside of emacs)
You can verify it yourself: C-h k K

or:
M-x describe-key
then press: K

**** Why useful?
You can read documentation using Emacs manpages navigation:
#+begin_src text
  Space       scroll down
  Backspace   scroll up
  q           quit
  g           refresh
  /           search
  n / p       next / previous search result
#+end_src

For a Linux-heavy workflow, this is pretty useful:
#+begin_src text
K
→ grep
→ find
→ fd
→ rg
→ git
→ systemctl
→ tmux
#+end_src

***** Important distinction
=manual-entry= is *not* the same as: =C-h f=: Describe an Emacs Lisp function
Example: C-h f find-file
=manual-entry=: Opens an external Unix manual

So:
#+begin_src text
C-h f        → Emacs function documentation
C-h v        → Emacs variable documentation
C-h k        → What does this key do?
K            → Unix man page
#+end_src

A nice mental model:
*Emacs help commands explain Emacs. =manual-entry= explains your
operating system and command-line tools.*

#+begin_src elisp
(defun dt/md-to-org (beg end)
  "Convert selected Markdown text to Org format in-place."
  (interactive "r")
  (unless (use-region-p)
    (user-error "No region selected"))

  (let* ((markdown (buffer-substring-no-properties beg end))
         (org-text
          (with-temp-buffer
            (insert markdown)
            (shell-command-on-region
             (point-min)
             (point-max)
             "pandoc -f markdown -t org"
             t t)

            ;; Remove CUSTOM_ID property drawers
            (goto-char (point-min))
            (while (re-search-forward
                    "^:PROPERTIES:\n:CUSTOM_ID:.*\n:END:\n?"
                    nil t)
              (replace-match ""))

            (buffer-string))))

    (delete-region beg end)
    (goto-char beg)
    (insert org-text)))

(defun dt/org-to-md (beg end)
  "Convert selected Org text to Markdown format in-place."
  (interactive "r")
  (unless (use-region-p)
    (user-error "No region selected"))

  (let* ((org-text (buffer-substring-no-properties beg end))
         (md-text
          (with-temp-buffer
            (insert org-text)
            (shell-command-on-region
             (point-min)
             (point-max)
             "pandoc -f org -t gfm"
             t t)

            ;; Strip pandoc markdown attributes like {.done .DONE}
            (goto-char (point-min))
            (while (re-search-forward "{[^}]*}" nil t)
              (replace-match ""))

            (buffer-string))))

    (delete-region beg end)
    (goto-char beg)
    (insert md-text)))
#+end_src

- Know what you know/not know.
- Understand *how* you learn.
- Monitor whether you actually understand.
- Change your learning strategy if current strategy not working.

"I think I understand Emacs buffers, but I cannot explain them without

** DONE How to select everything that does not match a regex in Neovim
There are several meanings of "select", so the best method depends on
what you want to do.

*** 1. Select lines that *do not* match a pattern
Suppose you have:
apple
banana
apple
orange
apple

To select lines that doesn't contain =apple=: =:v/apple/d=

*** 2. Delete everything that doesn't match a regex
For example:
- keep only lines containing a number: =:v/\d/d=
- Keep only lines containing a URL: =:v/https?:///d=
- Keep only lines beginning with =TODO=: =:v/^TODO/d=

*** 3. Select all text that does not match a regex
Vim does not have a simple universal command meaning: "Select every
character that is not matched by this regex."

because regex matches can be variable-length and may overlap.

- Usually, you want one of these instead:
  - Invert a regex using =@!=.
  - Use =:v= for lines.
  - Use =:g!//command=.

*** Use a search pattern and operate on matches.
For example, match a character that is *not* a digit: =[^0-9]=

This is called a *negated character class*. =[^a]= means:
Match one character that is not "a".

Important distinction: =[^abc]=
means: One character that is neither a, b, nor c.
It does *not* mean: "Anything that does not contain the word abc."

*** The most useful practical pattern
If your goal is: "Keep only lines matching X", use =:v/X/d=

If your goal is: "Delete lines matching X", use =:g/X/d=

** =<()= (Process Substitution) in Bash
=<(command)= runs a command and exposes its output as if it were a file.
#+begin_src sh
diff <(sort file1.txt) <(sort file2.txt)
#+end_src

Instead of:
#+begin_src sh
sort file1.txt > /tmp/a
sort file2.txt > /tmp/b
diff /tmp/a /tmp/b
#+end_src

Why it's useful: - No temporary files. - Cleaner scripts. - Works with programs that expect filenames.

** Common examples
Compare command outputs
#+begin_src sh
diff <(ls dir1) <(ls dir2)
#+end_src

Compare sorted files
#+begin_src sh
diff <(sort a.txt) <(sort b.txt)
#+end_src

Grep multiple command outputs
#+begin_src sh
grep error <(journalctl)
#+end_src
Feed output as a file
Some programs only accept files.

#+begin_src sh
vim <(curl -s example.com)
#+end_src

Multiple inputs
#+begin_src sh
paste <(seq 5) <(yes X | head -5)
#+end_src
Output
#+begin_src text
1   X
2   X
3   X
4   X
5   X
#+end_src

** What's actually happening?
#+begin_src sh
echo <(echo hello)
#+end_src
prints something like
#+begin_src text
/dev/fd/63
#+end_src
Bash creates a special file descriptor.

** Related: =>(...)=
Opposite direction.
#+begin_src sh
echo "hello" | tee >(wc -c)
#+end_src
The output is sent into another command.
Useful for logging while continuing a pipeline.

** Tricks
Find differences between directories
#+begin_src sh
diff <(find dir1 | sort) <(find dir2 | sort)
#+end_src
#baka what was that?

Compare git branches
#+begin_src sh
diff \
  <(git show main:file.txt) \
  <(git show feature:file.txt)
#+end_src

Merge command outputs
#+begin_src sh
cat <(date) <(hostname) <(uptime)
#+end_src

Search command output
#+begin_src sh
rg foo <(git ls-files)
#+end_src

** Remember
- =<(...)= → command output becomes a file.
- =>(...)= → command input becomes a file.
it's one of Bash's most useful features for eliminating temporary files.
