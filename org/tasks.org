*** ✅ Simple meaning of /Unit Testing/
:PROPERTIES:
:CUSTOM_ID: simple-meaning-of-unit-testing
:END:
*Unit testing = testing small pieces of your code (units) to make sure
each one works correctly.*

- A /unit/ is usually a *method/function*
- You test it *independently* from the rest of the program

👉 Think of it like:

#+begin_quote
Instead of testing the whole car, you test the *engine alone*, then the
*brakes alone*, etc.
#+end_quote

--------------

*** 💡 Why it matters
:PROPERTIES:
:CUSTOM_ID: why-it-matters
:END:
- Finds bugs early 🐛
- Makes your code safer to change
- Helps you understand your own code better

--------------

*** 🧠 Simple C# example
:PROPERTIES:
:CUSTOM_ID: simple-c-example
:END:
Let's say you wrote this method:

#+begin_src csharp
public int Add(int a, int b)
{
    return a + b;
}
#+end_src

A *unit test* checks if it works correctly:

#+begin_src csharp
[Test]
public void Add_ShouldReturnCorrectSum()
{
    int result = Add(2, 3);

    Assert.AreEqual(5, result);
}
#+end_src

👉 This test says:

- Call =Add(2, 3)=
- Expect the result to be =5=

--------------

*** 🧰 Tools in C# (very common)
:PROPERTIES:
:CUSTOM_ID: tools-in-c-very-common
:END:
You usually use frameworks like:

- NUnit
- xUnit
- MSTest

They provide:

- =[Test]= → marks a test
- =Assert= → checks results

*** 🔑 Key concepts (easy terms)
:PROPERTIES:
:CUSTOM_ID: key-concepts-easy-terms
:END:
- *Test case* → one check (e.g., 2+3=5)
- *Assert* → verify result
- *Test suite* → group of tests
- *Pass/Fail* → result of test
